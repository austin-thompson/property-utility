# Cycles

The roadmap is the stable high-level guide for the project. Cycle documents capture the concrete implementation slices for the current repository state.

Use the roadmap to understand where the project is heading. Use the current and historical cycle documents to understand what was actually implemented, what changed, what remains open, and how the work was verified. When a new cycle begins, it should be represented by a lightweight outline document before full implementation work starts.

Cycle documents should stay focused on what was actually attempted, what changed, what remains open, and how the work was verified. They are best treated as lightweight records of slices rather than as the primary source of product direction.

Each cycle should include:

- objective
- scope covered
- outcomes
- problems and gaps identified
- verification evidence
- follow-up items
